# Acceptance criteria

Status values: **passed** · **failed** · **blocked** · **not implemented**. Each criterion separates
*fixture verification* (automated tests on synthetic/recorded data, run in this session) from
*live verification* (real platforms, real models, real devices). "blocked" means the capability is
implemented but could not be exercised in the build environment (no social credentials, no Ollama,
no Docker daemon, no Android SDK/Xcode). Commands and raw results are in docs/VERIFICATION.md.
